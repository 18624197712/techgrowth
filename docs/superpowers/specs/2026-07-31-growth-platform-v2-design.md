# TechGrowth 成长平台 v2 设计

## 文档状态

本设计在 `2026-07-30-intelligent-coach-curriculum-radar-design.md` 已实现能力上继续演进。若两份文档存在冲突，以本文对课程路线、任务契约、导师工具、雷达来源、仓库匹配和 Web 布局的定义为准。

## 目标

把当前按四类通用能力轮转的成长系统升级为可选择技术栈、可解释进度、可操作导师和可观测数据的一体化个人成长平台。用户每天仍只投入 30 至 45 分钟，所有晋级必须由通过审阅的代码、Commit、答案、测验或测试报告支持。

本次交付解决以下问题：

1. Windows 连接器配对失败和项目与仓库匹配不稳定。
2. 缺少统一查看学习、雷达、仓库和 AI 运行数据的数据中台。
3. 国内技术来源不足，深圳 ECS 获取国外来源时缺少可控降级。
4. 今日任务描述不够明确，缺少完整理论、题目、步骤、提示和重新出题能力。
5. 导师只能识别有限意图，不能通过 Function Calling 操作平台模块。
6. 缺少从初级到架构师的可选技术栈课程和数据结构与算法路线。
7. 导师字体偏小且侧栏宽度固定。

不包含多人协作、公开注册、自动运行仓库代码、自动安装未签名连接器、任意网络访问或由模型直接修改技能等级。

## 总体架构

继续采用模块化单体：FastAPI 提供领域服务和 API，Worker 负责定时任务，React 提供工作台，PostgreSQL/pgvector 保存业务数据，Windows 连接器只主动发起 HTTPS 请求。暂不拆分微服务或引入消息总线。

新增四个清晰边界：

- `CurriculumService`：课程目录、激活路线、进度和节点资格。
- `TaskGenerationService`：节点选择、任务生成、重新出题和提示揭示。
- `ToolRegistry`：导师可调用工具的 Schema、权限、确认和执行。
- `AnalyticsService`：从业务事实计算数据中台查询模型，不维护不可解释的独立总分。

模块只能通过领域服务修改状态。模型输出先经 Pydantic Schema 和领域策略校验，模型不能直接访问数据库、文件系统、凭据或任意 URL。

## 课程体系 v2

### 路线模型

课程目录升级为版本化 `v2`，提供四条可选择主路线：

| 路线 | 基础 | 实践 | 生产 | 架构 |
| --- | --- | --- | --- | --- |
| Java + Spring Cloud | Java/Spring 核心 | 服务开发与中间件 | 稳定性与可观测性 | 分布式系统与架构治理 |
| Python + FastAPI/AI | Python/FastAPI/模型 API | RAG、Agent 与评测 | 安全、成本与部署 | AI 平台和系统架构 |
| Go | 语言、并发与工具链 | 网络服务与数据访问 | 性能、可靠性与云原生 | 高并发和分布式架构 |
| Node.js + TypeScript | TypeScript/Node 核心 | API、事件与测试 | 性能、安全与运维 | 平台化和系统架构 |

数据结构与算法作为独立公共副线，覆盖复杂度、线性结构、树与图、排序搜索、贪心、回溯、动态规划及工程算法。用户可以配置每周算法任务次数；算法任务在当天替代主路线任务，不额外增加每日任务量。

任意时刻只有一条主路线处于激活状态。切换路线不删除或重置其他路线进度。旧 `v1` 任务和证据保持只读可追溯，并通过稳定映射计入最接近的 v2 节点；无法可靠映射的证据保留为通用证据，不自动完成节点。

### 节点与晋级

每个课程节点包含：

- 稳定 `track_key`、`stage_key`、`node_key` 和课程版本。
- 前置节点、理论目标、实践目标和仓库技术关键词。
- 推荐题型、交付物类型、验收类型、Rubric 模板和可靠参考来源。
- 完成条件和进入下一阶段所需的关键证据。

节点只有在关联提交通过审阅并产生 `SkillEvidence` 后完成。阶段晋级由确定性规则计算，AI 只能解释差距或生成符合当前节点的任务。

### 每日选择规则

1. 未通过的聚焦补做优先。
2. 在当天应安排算法且存在合格算法节点时选择算法副线。
3. 否则从当前激活主路线选择第一个前置条件满足但尚未完成的节点。
4. 普通重新出题保持同一路线、阶段和能力目标，仅更换场景或题型。
5. 最近 14 天不重复节点主题；补做任务例外。
6. 每天最多保留一个当前有效任务，被替换任务标记为 `replaced`，不计为失败。

## 完整任务契约

`LearningTask` 在现有结构化步骤、交付物、验收和 Rubric 基础上增加：

- `task_kind`：理论问答、编码、调试、设计、评审或算法。
- `learning_objectives`：完成后可验证的能力。
- `theory_brief`：完成任务必须理解的概念和边界。
- `problem_statement`：无歧义题目、输入输出或业务场景。
- `constraints`：技术限制、禁止项、规模和质量要求。
- `starter_context`：允许使用的代码上下文、仓库位置或示例数据。
- `hints`：方向、关键步骤、接近答案三级提示。
- `solution_outline`：提交后或用户确认后揭示的参考思路，不是可直接复制的完整答案。
- `replaced_task_id`、`regeneration_reason`：重新出题审计链。

任务必须满足：

- 总时长和步骤时长均落在 30 至 45 分钟。
- 至少一个理论目标、一个实践目标、一个明确交付物和两个验收检查。
- 题目包含成功条件；编码和算法题必须说明输入输出或业务约束。
- 至少一个关键 Rubric 项，0 至 4 分锚点完整。
- 引用只能来自提供给模型的课程或雷达来源 ID。
- 未使用提示时不显示 `solution_outline`；每次揭示提示记录级别供审阅参考，但不直接判定不通过。

`POST /tasks/{id}/regenerate` 接收可选原因和偏好。服务端锁定当前任务，拒绝替换已提交或已完成任务，生成合规新任务后在一个事务中将旧任务标记为 `replaced`。若模型失败，不改变旧任务。请求支持幂等键，避免重复点击创建多个任务。

## AI 导师与 Function Calling

### 工具注册表

导师不再为每类意图编写独立写操作分支，而是使用白名单 `ToolRegistry`。每个工具声明名称、用途、Pydantic 参数 Schema、只读或写入级别、上下文加载器、执行器和结果 Schema。

首版工具如下：

| 工具 | 类型 | 作用 |
| --- | --- | --- |
| `get_active_curriculum` | 只读 | 查询当前主路线、算法设置和下一节点 |
| `get_skill_gaps` | 只读 | 查询证据支持的技能短板 |
| `get_today_task` | 只读 | 查询今日任务和可见提示 |
| `get_radar_digest` | 只读 | 查询雷达热点与来源状态 |
| `get_repository_metrics` | 只读 | 查询仓库匹配和质量指标 |
| `get_growth_evidence` | 只读 | 查询近期证据与晋级差距 |
| `regenerate_today_task` | 写入 | 按当前节点重新出题 |
| `switch_primary_track` | 写入 | 切换激活主路线并保留进度 |
| `set_algorithm_frequency` | 写入 | 调整每周算法任务次数 |
| `create_task_from_radar` | 写入 | 将雷达条目转成课程兼容任务 |
| `request_repository_sync` | 写入 | 给在线连接器创建同步任务 |

只读工具可在一次导师请求中自动调用，总调用数和结果字符数受限。写入工具只创建 15 分钟有效的一次性确认提议，必须通过 CSRF 保护的确认接口执行。执行器再次验证登录会话、资源归属、参数和当前状态；重复确认保持幂等。

### 模型协议与回退

优先使用 OpenAI 兼容 `tools`/`tool_choice` 协议。若配置的模型端点不支持原生 Function Calling，工作流回退为 Pydantic 校验的结构化工具决策，但仍经过同一注册表和确认层。模型最多执行三轮只读工具调用，禁止递归调用和未注册工具。

SSE 增加 `tool_call`、`tool_result` 和通用 `action_proposal` 事件。所有调用保存脱敏后的工具名、参数摘要、状态、耗时和 token 使用；不保存 API Key、代码正文或敏感响应。

## 数据中台

### 页面结构

主导航新增“数据中台”和“课程中心”。数据中台默认打开统一总览，并提供学习进度、雷达趋势、仓库质量和 AI 运行四个下钻视图。日期范围支持最近 7 天、30 天、90 天和全部。

统一总览展示：本周有效学习分钟、通过任务数、主路线阶段、距离下一阶段所缺证据、雷达消化率和仓库质量指标。每个数值可下钻到构成事实。

### 指标定义

- 有效学习分钟：已提交任务的计划分钟，按实际记录上限截断，防止异常值。
- 任务通过率：选定时间内通过审阅的已审任务数除以全部已审任务数。
- 课程完成率：已通过证据的节点数除以当前路线全部节点数，并按阶段单独展示。
- 雷达消化率：产生收藏、任务或导师查询的雷达条目数除以已展示条目数。
- 测试文件占比：连接器识别的测试文件数除以可分析源文件数；不宣称等同于测试覆盖率。
- 仓库活跃度：提交天数和 Commit 数分别展示，不合成为主观分数。
- AI 成功率：成功完成的模型调用数除以全部模型调用数，按聊天、任务和审阅区分。

`AnalyticsService` 以聚合查询返回这些结果，不在首版维护异步物化表。API 为 `/analytics/overview`、`/analytics/learning`、`/analytics/radar`、`/analytics/repositories` 和 `/analytics/ai-runs`，统一接受日期范围并返回指标定义和构成数据。

## 技术雷达 v2

保留每天 `08:00 Asia/Shanghai` 自动抓取、`08:10` 生成任务和手动补跑。来源改为注册表，每个来源声明地区、类型、URL 候选、可信度、标签、解析器和启用状态；页面不再硬编码来源总数。

国内首批来源优先使用公开 RSS、Atom 或正式 API：InfoQ 中文、开源中国、SegmentFault、V2EX 技术节点、阮一峰周刊、机器之心，以及可稳定获取的阿里云、腾讯云和华为云开发者内容。上线前逐一验证可访问性、内容许可和解析稳定性；没有公开接口或明确禁止自动抓取的站点不接入。

国外现有来源继续保留。`TG_OUTBOUND_PROXY_URL` 只用于雷达请求，不用于 Chat、Embedding、GitHub 或连接器凭据。国内源不经过代理；代理失败时继续国内源并在来源健康度中显示失败原因。每个来源独立重试和熔断，全部失败时保留历史数据。

来源状态包含最近成功时间、最近尝试时间、连续失败次数、最近脱敏错误和本次新增数。Radar Job 根据动态启用来源数返回统计，修复 Web 中硬编码 `/6` 的显示。

## 项目与仓库连接

### 统一仓库身份

新增 `canonical_remote_url`，统一处理 HTTPS/SSH GitHub URL、大小写、尾部 `.git` 和无关尾斜杠。同一仓库的服务端身份优先使用：

1. Provider 加仓库稳定 ID。
2. 规范化 Remote URL。
3. 无 Remote 仓库使用设备 ID 加授权根目录内相对路径指纹。

连接器同步不再依赖显示名称完全相同。唯一匹配时自动关联；多个候选或 Remote 变化时进入 `needs_confirmation`，由用户在 Web 选择已有项目或新建项目。关联、拒绝和重新关联均保留审计记录。

### Windows 连接器诊断

配对前增加只读连接测试，分别诊断 URL 规范、DNS、TCP、TLS、HTTP 状态和 API 健康。错误映射为中文稳定码：备案/接入拦截、TLS 被重置、证书验证、DNS、超时、配对码无效、签名失败和设备撤销。

当前公网域名的 `SSL: UNEXPECTED_EOF_WHILE_READING` 已在 Python 和 curl 中复现，HTTP 80 返回阿里云 `Non-compliance ICP Filing`。这是域名备案接入层在 TLS 握手阶段重置连接，不通过关闭证书校验或修改 Ed25519 逻辑绕过。生产部署必须先在阿里云完成备案接入并确认普通 HTTPS 客户端可访问，再发布连接器。

### GitHub 只读接入

设置页增加只读 Fine-grained PAT。Token 使用现有凭据加密机制保存，权限检查只接受仓库元数据和 Contents 只读范围。用户显式选择仓库后导入元数据；Token 不进入模型上下文。GitHub 与连接器发现同一规范化 Remote 时合并为同一项目并保留两个来源状态。

新增 API：`/github/connection`、`/github/repositories`、`/github/imports`、`/repositories/{id}/match` 和 `/repositories/{id}/sync`。网络或权限错误必须区分展示，禁止把响应正文或 Token 写入日志。

## Web 交互

桌面布局保持左侧导航、中心工作区和右侧导师。中心新增数据中台、课程中心和完整任务详情。今日任务的“重新出题”按钮先选择可选原因，再展示替换确认；生成过程中旧任务保持可用。

导师正文使用 15px 字号。侧栏通过左侧拖动手柄在 320 至 720px 之间调整，并把宽度保存在浏览器本地；双击手柄恢复默认宽度。键盘用户可聚焦手柄并用方向键调整。移动端导师使用全屏抽屉，不保留桌面宽度。

课程中心展示五条路线及各自进度。切换主路线需要确认，算法副线使用每周次数选择器。解决思路默认折叠，分三级提示；完整参考思路在首次提交后或主动二次确认后显示。

## 数据迁移与兼容

使用向后兼容 Alembic 迁移新增课程激活状态、路线进度、任务类型/理论/题目/提示/替换链、仓库统一身份、GitHub 凭据引用和来源健康数据。新增列先允许空值或提供服务端默认值，旧镜像仍能短暂运行。数据回填和 v1 到 v2 映射使用独立可重入命令，部署前后均可安全重跑。

Web 在迁移窗口兼容旧任务字段。任务替换、工具确认和仓库匹配都使用事务与幂等键。导出接口增加新数据，但不导出 Provider Key、GitHub Token、连接器私钥或聊天中的敏感上下文。

## 安全、错误和可观察性

- Function Calling 只接受注册工具和严格 Schema，写操作必须确认。
- 仓库内容、雷达内容和用户提交始终标记为不可信数据，防止提示注入。
- GitHub PAT、模型密钥和连接器密钥使用已有加密边界，日志统一脱敏。
- 连接器不自动执行代码，不扩大授权目录或上传范围。
- 模型、雷达、GitHub 和连接器错误使用稳定错误码与中文可行动信息。
- `AgentRun` 记录工作流、模型、状态、token、耗时和脱敏错误；数据中台只读取汇总。
- 所有外部请求设置连接/读取超时、有限重试和并发上限。

## 测试策略

### 后端单元与集成

- v2 五路线目录、前置节点、切换保留进度、算法频率和证据晋级。
- 完整任务 Schema、提示揭示、14 天去重、替换事务、幂等和失败保留旧题。
- 工具 Schema、只读自动执行、写入确认、过期、重复确认、调用上限和敏感字段过滤。
- 数据中台每个指标的边界、空数据、日期范围和构成一致性。
- 国内来源解析、动态来源计数、部分失败、代理隔离和 08:00 补跑。
- Remote 规范化、唯一匹配、歧义确认、重复来源合并和 GitHub 权限错误。

### 连接器

- 连接预检对 DNS、TLS 重置、证书错误、HTTP 备案拦截和 API 错误的映射。
- 不同 URL 形式的同仓库身份、Remote 变化和无 Remote 指纹。
- 继续覆盖授权目录、路径穿越、符号链接、密钥过滤、离线续传和撤销。

### Web 与生产

- Web 测试覆盖数据中台下钻、路线切换、算法频率、任务重新生成、分级提示、通用工具确认、仓库手动匹配、GitHub 导入和导师宽度持久化。
- Playwright 覆盖从选择路线、完成任务、审阅证据到数据更新的主闭环。
- 生产先验证备案域名可被 curl 和 Python TLS 客户端访问，再验证浏览器和连接器。
- 部署后验证国内/国外来源隔离、08:00 调度、真实 Function Calling 或结构化回退、GitHub 只读权限和连接器同步。

## 发布顺序

1. 迁移、课程 v2 与任务契约。
2. 重新出题、提示揭示和课程中心。
3. 通用 Tool Registry 与导师交互。
4. AnalyticsService 与数据中台。
5. 国内雷达来源和动态健康状态。
6. 统一仓库身份、GitHub 接入和连接器诊断。

每个阶段都先写失败测试，完成最小实现后运行聚焦测试；合并前运行 API、Web 和 Connector 全量验证。生产部署遵循先备份、向后兼容迁移、带 Git SHA 镜像、健康检查和失败回滚流程。
